STAGE 2予定の取得と統合 fetch_schedule.py

  1. 公式カレンダー

    ルール

    予定の一覧と各イベントページを読み、時刻・会場・出演メンバーを取り出す。毎回すべて読み直すので、ページが書き換わればそのまま反映される。

  2. お知らせ記事（過去 365 日）

    【開催日】の記事・月ごとのスケジュール公開日付と予定名を読むルール
    ルールで読めない記事（ラジオ出演のまとめなど）番組の予定を読むAIpost_ai.json

    読んだ予定は、公式カレンダーの同じ予定と 1 件にまとめる。

  3. 公式 X（前回より新しい投稿）

    投稿ごとに、次のどれかとして読む。

    1 行目が「…中止のお知らせ」「…欠席のお知らせ」中止・欠席の告知ルールx_notices.json
    「🎤出演情報🎤」「#あしたのたかねこ」など新しい予定の告知ルールAI（読めないとき）x_events.json
    本文に「変更・中止・欠席・延期」など時刻・会場の変更、書き方の決まっていない中止・欠席AIx_notices.json

    新しい予定は公式カレンダーの予定とまとめる。まとめるときは空いている項目を埋めるだけで、公式の値は上書きしない。

  4. Eventernote（非公式）

    ルール

    公式にまだない出演情報を補う。取得に失敗しても続ける。

  5. 仮の会場を補う

    「東京都内某所」のままの予定に、同じ日の記事から会場名を補い、会場の情報元を結び付ける。

  6. 告知を予定に反映

    x_notices.json
    中止・延期・欠席予定名の先頭に【中止】【延期】【城月欠席】などを付ける。個別メンバーの予定は出演者を直す
    時刻・会場の変更公式の値が変更前のままなら書き換える。すでに変更後なら何もせず、どちらとも違えば公式を優先する

  7. 安全策

    前回あった予定の 30% 以上（かつ 5 件以上）が見つからなければ、何も書き出さずに失敗として止める。

  8. 過去の予定の引き継ぎと並べ替え

    開始日より前の予定は前回の schedule.csv から引き継ぎ、終わった予定に「済」を付ける。

  9. 参加メモ

    AImemos.json

    公式の案内がある予定に、当日に必要なことの要約を付ける。案内の文章が変わった予定だけ作り直す。

  10. ID を付ける

    日付と情報元から ID を作る。情報元が変わった予定（X → 公式カレンダーなど）は前回の ID を引き継ぎ、カレンダーの予定や ★ の印が外れないようにする。

  11. 予定を書き出す

    schedule.md・schedule.csv・schedule.ics・events/<uid>.ics。【中止】【延期】の予定はカレンダーで「キャンセル」になる。

  12. 申込・締切

    ルール

    お知らせ記事の「受付期間」などから日時を読み、deadlines.md・.csv・.ics に書き出す。受付期間の途中で公開された記事は受付開始も残す。最近の記事で公開日より前の日付があれば、記載ミスの可能性として書き出す。

AI を使っているところ

処理対象保存先
お知らせ記事の読み取りルールで読めない記事post_ai.json
公式 X の新しい予定ルールで読めない投稿x_events.json
公式 X の変更・中止本文に変更・中止などを含む投稿（月 2〜3 件）x_notices.json
参加メモ公式の案内がある予定memos.json

どれも同じ考え方です。AI は読むだけで、日付・予定名・時刻・会場が本文に実際に書かれているかをコードが確かめてから使います。API キーがなければ AI の部分だけ飛ばし、ルールの処理はそのまま動きます。
